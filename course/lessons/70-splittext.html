SplitText — The Apple/Netflix Headline Reveal

You've seen it on every Apple keynote page and Netflix title card: a headline whose letters rise into view as if from behind a mask. Here's exactly how it's done — and it's three lines of GSAP.

Type can't be animated character-by-character out of the box — a heading is one text node, not a hundred letters. SplitText fixes that: it splits your text into individual <span>s for characters, words and lines, so you can animate each one. Combined with a line mask, you get the unmistakable cinematic reveal where letters slide up from behind an invisible edge.

The masked headline reveal

Live demo · SplitText
src/lib/SplitHeadline.svelte 
<script lang="ts">
  import { gsap } from 'gsap';
  import { SplitText } from 'gsap/SplitText';
  import type { Attachment } from 'svelte/attachments';

  gsap.registerPlugin(SplitText);

  let { text }: { text: string } = $props();

  // The signature "cinematic headline": split the text into individual characters
  // (and lines), then reveal them with a masked, staggered rise. SplitText wraps
  // each character in its own <span> for you — animating that by hand is misery.
  const cinematicReveal: Attachment<HTMLElement> = (node) => {
    let split: SplitText | undefined;

    // Wait for fonts so the split measures the real glyph widths.
    document.fonts.ready.then(() => {
      split = new SplitText(node, {
        type: 'lines,chars',
        linesClass: 'line',
        // mask:'lines' clips each line so characters rise out from behind it —
        // the polished, "premium" version of the effect.
        mask: 'lines'
      });

      gsap.from(split.chars, {
        yPercent: 120,
        opacity: 0,
        duration: 0.9,
        ease: 'expo.out',
        stagger: { each: 0.025, from: 'start' }
      });
    });

    return () => split?.revert(); // restores the original, un-split markup
  };
</script>

<h1 class="headline" {@attach cinematicReveal}>{text}</h1>

<style>
  .headline {
    font-size: clamp(2.4rem, 9vw, 6rem);
    font-weight: 800;
    letter-spacing: -0.03em;
    line-height: 1.02;
    text-align: center;
    max-width: 14ch;
    background: linear-gradient(135deg, #f4f6fb, #aab2c5);
    -webkit-background-clip: text;
    background-clip: text;
    color: transparent;
  }
  /* SplitText adds .line per line; we hide overflow so masked chars clip cleanly. */
  .headline :global(.line) { overflow: hidden; }
</style>

Why the mask makes it cinematic

Splitting characters and staggering a yPercent rise already looks good. The mask is what makes it look expensive. By setting mask: 'lines', SplitText wraps each line in a clipped container. The characters animate up from yPercent: 120 — fully below their line — and emerge from behind that clip, so there's no "ghost" of the letter visible before it arrives. That clean edge is the entire difference between "nice" and "shot on a film set."

Two non-negotiables for crisp text reveals. First, split after document.fonts.ready — if you split before the web font loads, the lines wrap at the wrong widths and reflow mid-animation. Second, always split.revert() on cleanup. SplitText injects a lot of markup; reverting restores your original, accessible heading (vital for screen readers and for re-running the effect). Our attachment does both.

Beyond the entrance

Once text is split you can do far more than reveal it: animate a gradient sweep across the characters, scrub the reveal to scroll (combine with last lesson's ScrollTrigger), or build a per-letter hover. SplitText also auto-adds aria-label with the original text so the split version stays accessible. This single plugin is responsible for a huge fraction of the "how did they do that?" typography on the web.
