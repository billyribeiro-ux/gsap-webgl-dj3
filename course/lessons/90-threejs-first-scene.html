M9 · WebGL / Three.js

Your First 3D Scene + Render Loop

Two dimensions aren't always enough. Three.js gives you a real-time 3D engine in the browser — scene, camera, lights, materials and a render loop running on the GPU. Let's light up your first object.

WebGL lets the browser talk directly to the GPU, but its raw API is brutally low-level. Three.js is the layer almost everyone uses on top — it gives you intuitive objects (meshes, cameras, lights) and handles the math. Every 3D product viewer, every immersive scrollytelling site, every "how is this in a browser?!" moment is almost certainly Three.js.

Your first lit, spinning object

Below is a faceted icosahedron, lit by a violet key light and a cyan rim light, rotating in a render loop. That's the entire skeleton of 3D on the web — and the code beside it is exactly what you'd drop into a SvelteKit component.

Live demo · Three.js (WebGL)
src/lib/ThreeScene.svelte 
<script lang="ts">
  import * as THREE from 'three';
  import type { Attachment } from 'svelte/attachments';

  // Every Three.js scene needs the same three things: a SCENE (the world), a
  // CAMERA (your eye), and a RENDERER (which paints the scene onto a <canvas>
  // each frame). Add a mesh + lights, spin it in a render loop, and you have 3D.
  const scene: Attachment<HTMLCanvasElement> = (canvas) => {
    const renderer = new THREE.WebGLRenderer({ canvas, antialias: true, alpha: true });
    renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

    const world = new THREE.Scene();
    const camera = new THREE.PerspectiveCamera(45, 1, 0.1, 100);
    camera.position.z = 4;

    // A mesh = geometry (shape) + material (surface). MeshStandardMaterial reacts
    // to light, which is what gives it that premium, physically-lit look.
    const geometry = new THREE.IcosahedronGeometry(1.2, 0);
    const material = new THREE.MeshStandardMaterial({
      color: 0x11141f,
      metalness: 0.6,
      roughness: 0.25,
      flatShading: true
    });
    const mesh = new THREE.Mesh(geometry, material);
    world.add(mesh);

    // Two coloured point lights are the whole "cinematic" trick — one warm-violet
    // key light, one cyan rim light, raking across the facets.
    const key = new THREE.PointLight(0x7c5cff, 80);
    key.position.set(3, 3, 4);
    const rim = new THREE.PointLight(0x19e3d6, 60);
    rim.position.set(-4, -2, 2);
    world.add(key, rim, new THREE.AmbientLight(0xffffff, 0.15));

    function resize(): void {
      const { clientWidth: w, clientHeight: h } = canvas;
      renderer.setSize(w, h, false);
      camera.aspect = w / h;
      camera.updateProjectionMatrix();
    }
    const ro = new ResizeObserver(resize);
    ro.observe(canvas);
    resize();

    // The render loop: rotate a touch, then draw. ~60 times a second.
    let raf = 0;
    const tick = (): void => {
      mesh.rotation.x += 0.004;
      mesh.rotation.y += 0.006;
      renderer.render(world, camera);
      raf = requestAnimationFrame(tick);
    };
    tick();

    // Cleanup: stop the loop and free every GPU resource. Skipping this leaks
    // memory across SvelteKit navigations.
    return () => {
      cancelAnimationFrame(raf);
      ro.disconnect();
      geometry.dispose();
      material.dispose();
      renderer.dispose();
    };
  };
</script>

The three pillars of every scene

  • Scene — the 3D world. You add everything (meshes, lights, cameras, groups) to it. Think of it as the film set.
  • Camera — your viewpoint. A PerspectiveCamera mimics a real lens: things farther away look smaller. Its aspect must match your canvas, or everything stretches.
  • Renderer — the WebGLRenderer takes the scene and camera and paints one frame onto the canvas. Call renderer.render(scene, camera) every frame and you have animation.

Mesh = geometry + material, lit by lights

A mesh is a shape (geometry) wearing a surface (material). We used MeshStandardMaterial, which is physically based — it actually responds to light, which is why two coloured point lights raking across the facets look so rich. Swap to MeshBasicMaterial and it ignores lights entirely (flat, but cheap). Lighting is 80% of what makes 3D look expensive; spend your time there.

Dispose everything, every time. Geometries, materials and the renderer hold GPU memory that JavaScript's garbage collector can't reclaim. In a SvelteKit app, navigating away from a 3D page without calling geometry.dispose(), material.dispose() and renderer.dispose() leaks memory until the tab crashes. Our attachment's cleanup function does exactly this — which is why attachments are perfect for wrapping Three.js.
