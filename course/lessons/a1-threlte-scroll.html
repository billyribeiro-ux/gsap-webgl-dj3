Scroll-Linked & GSAP-Driven 3D

The crown jewel of immersive web design: a 3D object that turns and grows as you scroll. We link Threlte to the scrollbar — and discover the cleanest architecture in this whole course.

Scroll-linked 3D is the effect behind the most memorable product sites — a watch rotating to show its movement, a sneaker turning to reveal its sole, an abstract form blooming as you read. We already know the pieces: Threlte for declarative 3D (Module 10) and scroll progress (Module 6). Now we connect them with an architecture worth internalizing.

Scroll to drive the scene

Scroll the panel. The crystal rotates and grows in lockstep with your scroll position — and reverses perfectly when you scroll back. The 3D object knows nothing about scrolling; it just follows a single number.

Result · scroll ↓ (vanilla-Three preview of the Threlte scene)
src/lib/three/Spinner.svelte 
<script lang="ts">
  import { T, useTask } from '@threlte/core';
  import * as THREE from 'three';

  // A purely *driven* scene: it owns no animation logic of its own — it just maps
  // an incoming `progress` (0 → 1) onto rotation and scale. Whoever renders it
  // decides where progress comes from: scroll, a slider, a GSAP tween, anything.
  let { progress = 0 }: { progress?: number } = $props();

  let mesh = $state<THREE.Mesh>();

  // useTask applies the latest progress every frame, so motion stays smooth even
  // if progress updates less often than the display refreshes.
  useTask(() => {
    if (!mesh) return;
    mesh.rotation.y = progress * Math.PI * 2;
    mesh.rotation.x = progress * Math.PI;
    mesh.scale.setScalar(1 + progress * 0.6);
  });
</script>

<T.PerspectiveCamera makeDefault position={[0, 0, 5]} fov={45} />
<T.AmbientLight intensity={0.18} />
<T.PointLight position={[4, 4, 5]} color="#7c5cff" intensity={80} />
<T.PointLight position={[-5, -3, 4]} color="#19e3d6" intensity={60} />

<T.Mesh bind:ref={mesh}>
  <T.IcosahedronGeometry args={[1.3, 0]} />
  <T.MeshStandardMaterial color="#11141f" metalness={0.6} roughness={0.25} flatShading />
</T.Mesh>

And the wiring — a tall section with a sticky canvas that turns scroll into progress:

src/lib/three/ScrollLinked3D.svelte 
<script lang="ts">
  import { Canvas } from '@threlte/core';
  import Spinner from './Spinner.svelte';

  // The wiring: a tall section with a sticky canvas. As the section scrolls past,
  // we compute how far through it we are (0 → 1) and feed that to the 3D scene.
  // Because Spinner just consumes `progress`, the scroll math lives entirely here —
  // clean separation between "what drives the animation" and "what the animation is."
  let progress = $state(0);
  let section: HTMLElement | undefined = $state();

  function update(): void {
    if (!section) return;
    const rect = section.getBoundingClientRect();
    const total = section.offsetHeight - window.innerHeight;
    // -rect.top goes from 0 (top aligned) to `total` (bottom aligned).
    progress = Math.min(1, Math.max(0, -rect.top / total));
  }
</script>

<svelte:window onscroll={update} onresize={update} />

<section class="tall" bind:this={section}>
  <div class="sticky">
    <Canvas>
      <Spinner {progress} />
    </Canvas>
  </div>
</section>

<style>
  /* The section is 3 viewports tall, giving the scroll room to drive the scene. */
  .tall { height: 300vh; position: relative; }
  .sticky { position: sticky; top: 0; height: 100vh; }
</style>

The architecture: drive, don't entangle

This is the most important idea in the lesson, and it applies far beyond 3D. Notice the split:

  • Spinner is "driven." It takes a single progress prop and maps it to rotation and scale in useTask. It has no idea what drives it.
  • ScrollLinked3D is "the driver." It owns all the scroll math and simply hands progress down.

Because they're decoupled, you can swap the driver without touching the scene. Drive the same Spinner from a slider, from a GSAP timeline, from audio, from a drag gesture — the 3D code never changes. That separation between source of motion and expression of motion is how senior engineers keep complex interactive systems sane.

For production, smooth the progress. Raw scroll progress can be slightly jumpy. Pass it through a Spring (Module 3) or use GSAP ScrollTrigger's scrub: 1 to add a touch of lag, and the 3D glides rather than snaps. Same demo here uses vanilla Three.js because Threlte needs a build step — but the Threlte code in the panels produces exactly this, the clean, declarative way, in your SvelteKit app.

Add a real GLTF model via @threlte/extras's useGltf, light it well, link it to scroll like this, and you've built the centerpiece of a world-class product page. You now have every technique to do it.
