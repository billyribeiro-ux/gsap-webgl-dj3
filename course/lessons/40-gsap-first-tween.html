Your First Tween — to, from, fromTo

GSAP is the animation engine behind a huge share of award-winning sites — and as of 2025 it's 100% free, every plugin included. Let's write your first tween and learn the one pattern that makes GSAP feel native in Svelte.

A tween is GSAP's atom: "take these properties, on these targets, and interpolate them over this time with this ease." If CSS transitions are declarative ("ease changes to this property"), GSAP is imperative and far more powerful: it can animate any numeric property of anything — DOM, SVG, canvas, even plain JavaScript objects — and orchestrate hundreds of them in perfect sync.

Your first reveal

Below, three cards rise and fade into place, each staggered behind the last. The whole effect is a single gsap.from(...) call. Hit replay and watch the stagger ripple.

Live demo · GSAP
src/lib/GsapReveal.svelte 
<script lang="ts">
  import { gsap } from 'gsap';
  import type { Attachment } from 'svelte/attachments';

  type Feature = { title: string; body: string };

  let { features }: { features: Feature[] } = $props();

  // An attachment that animates the element's children in on mount. We wrap the
  // tween in a gsap.context() scoped to `node`; calling ctx.revert() in cleanup
  // kills every animation it created and restores the original styles. This is
  // THE pattern for using GSAP inside a component without leaks.
  const revealOnMount: Attachment<HTMLElement> = (node) => {
    const ctx = gsap.context(() => {
      gsap.from(node.children, {
        y: 48,
        opacity: 0,
        duration: 0.9,
        ease: 'expo.out',
        stagger: 0.12 // each child starts 120ms after the previous one
      });
    }, node);

    return () => ctx.revert();
  };
</script>

<div class="row" {@attach revealOnMount}>
  {#each features as feature (feature.title)}
    <article class="card">
      <h3>{feature.title}</h3>
      <p>{feature.body}</p>
    </article>
  {/each}
</div>

<style>
  .row { display: grid; gap: 1rem; grid-template-columns: repeat(auto-fit, minmax(140px, 1fr)); width: min(520px, 92%); }
  .card { padding: 1.2rem; border-radius: 14px; background: #11141f; border: 1px solid #1b2030; }
  .card h3 { margin: 0 0 0.35rem; color: #f4f6fb; font-size: 1rem; }
  .card p { margin: 0; color: #8b93a7; font-size: 0.85rem; }
</style>

to, from, fromTo — the three you'll reach for daily

  • gsap.to(target, {...}) — animate to these values from wherever the element currently is. The everyday workhorse.
  • gsap.from(target, {...}) — animate from these values to the element's natural state. Perfect for reveals: set the "before" and GSAP figures out the "after". That's what the demo uses.
  • gsap.fromTo(target, {from}, {to}) — you control both ends explicitly. Reach for it when the start state matters and you can't rely on the current styles.

Stagger: the cinematic multiplier

stagger: 0.12 tells GSAP to start each target 120ms after the previous one. That one property turns a flat group reveal into a wave. You can go further — stagger: { each: 0.1, from: 'center' } ripples outward from the middle; { grid: 'auto', from: 'edges' } animates a grid from its corners inward. This is how those "impossible" coordinated reveals are actually done.

The Svelte integration pattern — memorize this. Wrap GSAP work in gsap.context(() => {...}, node) inside an {@attach}, and return () => ctx.revert() as cleanup. context scopes selectors to your element and records every animation it makes; revert() undoes all of it when the component unmounts. No dangling tweens, no memory leaks, no manual bookkeeping. Every GSAP-in-Svelte example in this course uses exactly this shape.
