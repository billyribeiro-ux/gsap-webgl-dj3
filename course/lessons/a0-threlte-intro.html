M10 · Threlte (Svelte 5)

Declarative 3D with Threlte + useTask

Threlte is Three.js reimagined as Svelte components. The same 3D power you just learned, but declarative, reactive and a fraction of the code — the official Svelte way to build for WebGL.

Writing Three.js by hand means imperatively creating objects, adding them to the scene, wiring a render loop, handling resize and disposing everything on cleanup. Threlte wraps all of that in Svelte components. You declare your scene — <T.Mesh>, <T.PointLight> — and Threlte runs the renderer, the loop and the lifecycle for you. It's reactive too: change a prop with $state and the 3D updates instantly.

About this demo. Threlte is a Svelte library, so it needs a build step — it can't run in a plain HTML file like this page. The live demo below is the same scene rendered with vanilla Three.js so you can see the result; the code panels show the real Threlte version you'll paste into your SvelteKit app. They produce an identical spinning torus knot.

Declare it, don't build it

Result · (vanilla Three preview of the Threlte scene)
src/lib/three/Scene.svelte 
<script lang="ts">
  import { T, useTask } from '@threlte/core';
  import * as THREE from 'three';

  // In Threlte you don't *build* a scene imperatively — you *declare* it. Every
  // <T.Something> is a Three.js object expressed as a Svelte component. Props map
  // straight to Three.js properties, so <T.Mesh position={[0,1,0]}> sets
  // mesh.position. It's the entire Three.js API, reactive and component-shaped.
  let mesh = $state<THREE.Mesh>();

  // useTask runs its callback every frame (Threlte's render loop). `delta` is the
  // seconds since the last frame — multiply by it so motion is frame-rate
  // independent (smooth on a 60Hz laptop AND a 144Hz monitor).
  useTask((delta) => {
    if (mesh) {
      mesh.rotation.y += delta * 0.6;
      mesh.rotation.x += delta * 0.25;
    }
  });
</script>

<!-- A camera, looking down -Z from 5 units back. makeDefault tells Threlte to
     render through this one. -->
<T.PerspectiveCamera makeDefault position={[0, 0, 5]} fov={45} />

<!-- Lighting: a dim ambient fill plus two coloured points = cinematic facets. -->
<T.AmbientLight intensity={0.15} />
<T.PointLight position={[4, 4, 5]} color="#7c5cff" intensity={80} />
<T.PointLight position={[-5, -2, 3]} color="#19e3d6" intensity={60} />

<!-- The mesh: geometry + material declared as children, just like Three.js but
     readable. bind:ref hands us the underlying THREE.Mesh for the render loop. -->
<T.Mesh bind:ref={mesh}>
  <T.TorusKnotGeometry args={[1, 0.32, 160, 32]} />
  <T.MeshStandardMaterial color="#11141f" metalness={0.6} roughness={0.25} flatShading />
</T.Mesh>

And the entry point that mounts the renderer — one component, <Canvas>:

src/lib/three/ThrelteStage.svelte 
<script lang="ts">
  import { Canvas } from '@threlte/core';
  import Scene from './Scene.svelte';

  // <Canvas> is the single Threlte entry point. It creates the WebGLRenderer, the
  // default scene, the animation loop and the resize handling for you — then
  // renders whatever Svelte components you put inside. Everything 3D lives in here.
</script>

<div class="stage">
  <Canvas>
    <Scene />
  </Canvas>
</div>

The mental model

  • <Canvas> — the one wrapper. It builds the renderer, default scene, camera fallback, render loop and resize handling. Everything 3D goes inside it.
  • <T.X> — any Three.js class becomes a component. <T.Mesh> is new THREE.Mesh(); its props are the object's properties; its children are its constructor args (geometry, material). If you know Three.js, you already know Threlte.
  • useTask — Threlte's render loop hook. The callback runs every frame with a delta. This replaces your manual requestAnimationFrame — and Threlte cleans it up automatically.

Why frame-rate independence matters

Notice mesh.rotation.y += delta * 0.6 instead of a fixed += 0.01. delta is the time since the last frame, so the knot spins at the same real-world speed whether the user is on a 60Hz laptop or a 144Hz gaming monitor. Hard-coding per-frame increments is one of the most common 3D bugs — multiply by delta and it disappears.

Setup in your SvelteKit app: pnpm add three @threlte/core @threlte/extras. The @threlte/extras package adds the goodies — orbit controls, GLTF model loading, environment maps, instancing — that turn a demo into a product. Next lesson: linking 3D to scroll and driving it with GSAP.
