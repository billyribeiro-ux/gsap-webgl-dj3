A Gentle Introduction to Shaders

Shaders are where the truly impossible-looking web visuals live — liquid gradients, plasma, water, fire — all computed per-pixel on the GPU. They look like deep magic. Let's demystify the smallest useful one.

A shader is a small program that runs on the GPU, in parallel, for every pixel, every frame. There are two: the vertex shader positions geometry, and the fragment shader decides each pixel's color. That second one is where the art is. Because it runs on thousands of GPU cores at once, it can do things — flowing gradients, generative textures, fluid effects — that would melt the CPU.

An aurora from pure math

No image, no texture, no detailed geometry — just a flat plane and a fragment shader computing color from each pixel's position and the current time. The result flows forever.

Live demo · GLSL fragment shader
src/lib/ShaderPlane.svelte 
<script lang="ts">
  import * as THREE from 'three';
  import type { Attachment } from 'svelte/attachments';

  // A shader is a tiny program that runs on the GPU once per pixel, every frame.
  // The fragment shader below computes a flowing aurora purely from the pixel's
  // position (vUv) and a time uniform — no textures, no geometry detail. This is
  // where the most jaw-dropping web visuals come from.
  const vertexShader = /* glsl */ `
    varying vec2 vUv;
    void main() {
      vUv = uv;
      gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
    }
  `;

  const fragmentShader = /* glsl */ `
    uniform float uTime;
    varying vec2 vUv;
    void main() {
      vec2 uv = vUv;
      float t = uTime * 0.35;
      // Layered sine waves = organic, flowing interference pattern.
      float v = sin(uv.x * 6.0 + t)
              + sin(uv.y * 7.0 - t)
              + sin((uv.x + uv.y) * 5.0 + t * 1.3);
      v *= 0.33;
      vec3 violet = vec3(0.486, 0.360, 1.0);
      vec3 cyan   = vec3(0.098, 0.890, 0.839);
      vec3 pink   = vec3(1.0, 0.373, 0.620);
      vec3 col = mix(violet, cyan, smoothstep(-1.0, 1.0, v));
      col = mix(col, pink, smoothstep(0.4, 1.0, sin(uv.y * 3.0 + t)) * 0.6);
      gl_FragColor = vec4(col, 1.0);
    }
  `;

  const sketch: Attachment<HTMLCanvasElement> = (canvas) => {
    const renderer = new THREE.WebGLRenderer({ canvas, antialias: true });
    renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

    const scene = new THREE.Scene();
    // An orthographic camera + a 2×2 plane perfectly fills the clip space.
    const camera = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);

    const uniforms = { uTime: { value: 0 } };
    const material = new THREE.ShaderMaterial({ vertexShader, fragmentShader, uniforms });
    const quad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), material);
    scene.add(quad);

    const resize = () => renderer.setSize(canvas.clientWidth, canvas.clientHeight, false);
    const ro = new ResizeObserver(resize);
    ro.observe(canvas);
    resize();

    let raf = 0;
    const clock = new THREE.Clock();
    const tick = () => {
      uniforms.uTime.value = clock.getElapsedTime();
      renderer.render(scene, camera);
      raf = requestAnimationFrame(tick);
    };
    tick();

    return () => {
      cancelAnimationFrame(raf);
      ro.disconnect();
      quad.geometry.dispose();
      material.dispose();
      renderer.dispose();
    };
  };
</script>

<canvas class="viewport" {@attach sketch}></canvas>

How to read the fragment shader

  • vUv — the pixel's coordinate on the surface, from (0,0) to (1,1). It's passed from the vertex shader. Almost every effect starts here: "given where I am, what color am I?"
  • uniforms like uTime — values you send in from JavaScript, the same for every pixel. Feeding in elapsed time is what makes the pattern move; you'd also pass mouse position, audio levels, scroll, etc.
  • Layered sin() waves — adding a few sine functions of the coordinates produces an organic interference pattern. mix() and smoothstep() then blend our brand colors across it. That's the entire trick behind most "liquid gradient" hero backgrounds.
GLSL is a different language — start by editing, not writing. Shaders are written in GLSL (C-like), not JavaScript, and the mental model takes time. The fastest way in: take a shader like this and tweak numbers — change the wave frequencies, swap the colors, multiply uTime by a different speed. Watch what each change does. You'll build intuition far faster than by reading theory. In Threlte you can drop this same ShaderMaterial onto any <T.Mesh>.

Shader-driven backgrounds are everywhere in premium web design now — that subtly shifting gradient behind a hero is almost always a fragment shader. Master even the basics and you can produce visuals that look like nothing else on the web, at 60fps, in a few kilobytes of code.
