A force simulation is animation by physics rather than by keyframe. You define forces — repulsion between nodes, springs along links, a pull toward the center — and D3 iteratively nudges everything until it settles into a balanced layout. Network graphs, mind maps, bubble charts and clustering visuals all come from this one engine.

A living network — drag it

The nodes repel each other, the links pull them together, and the whole thing breathes into balance. Grab any node and drag — the network reorganizes around your hand in real time, then relaxes when you let go.

The forces, and the tick

  • forceManyBody() — every node pushes (negative strength) or pulls (positive) every other. Negative repulsion spreads the graph out so it's readable.
  • forceLink() — turns your links into springs with a target distance, holding connected nodes a comfortable gap apart.
  • forceCenter() — a gentle gravity toward the middle so the graph doesn't drift off-screen. Add forceCollide() to stop nodes overlapping.
  • The 'tick' handler — runs every simulation step. This is the animation loop: read each node's freshly computed x/y and write it to the SVG. D3 owns the physics; you own the rendering.
Dragging = pinning. Setting a node's fx/fy (fixed position) locks it under the pointer; the simulation flows around it. On release, set them back to null and the node rejoins the physics. And always sim.stop() on cleanup — a force simulation is a perpetual animation loop, so an orphaned one quietly burns CPU forever. Our $effect returns exactly that teardown.

This is also the bridge between D3 and Svelte at its finest: Svelte owns the component lifecycle, D3 owns the physics and SVG. Feed the simulation data from $state and it re-balances reactively — a live org chart, a dependency graph, a social network that grows as data arrives.
