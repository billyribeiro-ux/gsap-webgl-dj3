A shader is a small program that runs on the GPU, in parallel, for every pixel, every frame. There are two: the vertex shader positions geometry, and the fragment shader decides each pixel's color. That second one is where the art is. Because it runs on thousands of GPU cores at once, it can do things — flowing gradients, generative textures, fluid effects — that would melt the CPU.

An aurora from pure math

No image, no texture, no detailed geometry — just a flat plane and a fragment shader computing color from each pixel's position and the current time. The result flows forever.

How to read the fragment shader

  • vUv — the pixel's coordinate on the surface, from (0,0) to (1,1). It's passed from the vertex shader. Almost every effect starts here: "given where I am, what color am I?"
  • uniforms like uTime — values you send in from JavaScript, the same for every pixel. Feeding in elapsed time is what makes the pattern move; you'd also pass mouse position, audio levels, scroll, etc.
  • Layered sin() waves — adding a few sine functions of the coordinates produces an organic interference pattern. mix() and smoothstep() then blend our brand colors across it. That's the entire trick behind most "liquid gradient" hero backgrounds.
GLSL is a different language — start by editing, not writing. Shaders are written in GLSL (C-like), not JavaScript, and the mental model takes time. The fastest way in: take a shader like this and tweak numbers — change the wave frequencies, swap the colors, multiply uTime by a different speed. Watch what each change does. You'll build intuition far faster than by reading theory. In Threlte you can drop this same ShaderMaterial onto any <T.Mesh>.

Shader-driven backgrounds are everywhere in premium web design now — that subtly shifting gradient behind a hero is almost always a fragment shader. Master even the basics and you can produce visuals that look like nothing else on the web, at 60fps, in a few kilobytes of code.
