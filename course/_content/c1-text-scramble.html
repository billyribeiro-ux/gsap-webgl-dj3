The scramble (or "decode") effect resolves text out of noise: each character flips through random glyphs and then locks into its final letter. It reads as computation happening — perfect for loading states, hero headlines, and anything that wants a techno-thriller edge. The craft is in the timing: stagger when each character locks so the resolve feels organic, not like a wipe.

How the resolve works

  • Per-character timelines. Each slot gets a random start and end frame. Before start it shows nothing; between the two it shows a random glyph (re-rolled ~28% of frames so it flickers); at end it locks to the real character. Randomizing those windows is what makes the decode feel alive.
  • Render per-character, not as a string. We map the slots to individual <span>s in the template instead of building an HTML string. That keeps it XSS-safe (no {@html}) and lets us dim the still-scrambling glyphs versus the locked ones — a small touch that sells the "solving" feeling.
  • One requestAnimationFrame loop advances the frame counter and stops itself the instant every slot is solved. No wasted cycles.
Accessibility first. The churning glyphs are pure decoration, so the real string lives in aria-label and the animated spans are aria-hidden. A screen reader announces "ACCESS GRANTED" instantly, while sighted users get the show. And under prefers-reduced-motion the component skips straight to the final text — no churn at all.

Pair it with the rest

Scramble shines in combination: decode a headline as it enters on scroll (ScrollTrigger), run it on a stat that's also counting up with a Tween, or fire it on every route change for a UI that feels like a terminal. Swap the glyph set to katakana for a Matrix flavor, or to your brand's character set for something custom. Small effect, enormous personality.
