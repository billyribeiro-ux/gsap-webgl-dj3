How an edge-aware blur knows where the edges are

  • A guided blur. A plain blur would smear the whole image to mush. The à-trous filter weights each neighbouring pixel by how similar it is — comparing surface normal, object ID and colour. Neighbours on the same surface get full weight; those across an edge get almost none. Noise averages away; silhouettes stay razor-sharp.
  • "À-trous" = with holes. Instead of one big expensive blur, we run several cheap 3×3 passes, doubling the tap spacing each time (1, 2, 4, 8, 16 px). A few passes reach a huge radius for a fraction of the cost — the wavelet trick that makes it real-time.
  • The guide is free here. Because our scene is analytic (a few spheres), the denoise shader recomputes the exact normal and ID at every tap with a ray cast — no noise in the guide. In a real renderer these come from a G-buffer the path tracer writes alongside the noisy colour.
This is the whole game in real-time ray tracing. Trace one noisy sample, reproject last frame's result for temporal stability (SVGF), then run à-trous to clean it — that's how an RTX game ray-traces at 60fps. The cutting edge replaces the hand-tuned edge-stopping weights with a small neural network (NVIDIA's OptiX / DLSS Ray Reconstruction): a learned denoiser, trainable end-to-end with the same differentiable-render machinery behind Gaussian splatting.
